* Purpose
Star KB is the shared symbolic reasoning layer used by StarIntel actors and services. Canonical StarIntel JSON remains authoritative; Star KB deterministically projects that corpus into modular Prolog facts, safe reasoning tools, and—under the proposed policy-plane expansion—bounded policy/business decisions.

* Current phase
Research and the Prolog projection/query design are approved. The active bounded implementation is =prolog-star-kb=: canonical JSON -> lossless Prolog facts + semantic indexes + AI reasoning tools.

No bulk real-world ingestion is authorized in this slice.

A new design proposal, tracked by issue =#15=, maps StarIntel tenant/search authorization and broader declarative business logic into a shared bounded Prolog policy plane. This proposal does not supersede the active implementation slice or authorize a flag-day migration.

* Roadmap
1. Verify deterministic JSON -> Prolog projection and safe AI tool compiler.
2. Add SWI-Prolog CI smoke coverage.
3. Add query-server transport around the bounded semantic predicates.
4. Review/approve the policy-plane design from issue =#15=.
5. Add a versioned bounded policy ABI and tenant/grant semantic indexes.
6. Implement tenant-safe StarIntel Search policy: scope derivation, YaCy pre-filter obligations, authoritative post-authorization, and revocation epochs.
7. Generate MCP and Agent2Agent surfaces from the same tool catalog.
8. Add StarLang =kb=, =reason=, and policy bindings.
9. Migrate existing StarIntel Server authorization logic with parity fixtures rather than a flag-day rewrite.
10. Add entitlement, actor/target admission, ingest/projection, retention, scheduling, billing-classification, and migration policy modules in bounded slices.
11. Add engine adapters chosen by semantic capability.
12. Grow domain semantic indexes without sacrificing lossless generic projection.
13. Only then begin controlled corpus ingestion/materialization.

* Policy-plane boundary
The proposed policy plane follows one rule:

#+begin_quote
Prolog decides; the owning StarIntel service performs the effect transactionally.
#+end_quote

Star KB should own declarative decisions and explanations where useful, including tenancy/authorization, search disclosure, entitlements, actor/target admission, ingest policy, projection/redaction, retention classification, scheduling/admission, billing classification, and migration compatibility.

It should not own credential verification, secrets, database transactions/CAS, Rabbit/Valkey mutation, leases/fencing, payment ledgers, cryptographic signing, full-text execution, or privileged side effects.
