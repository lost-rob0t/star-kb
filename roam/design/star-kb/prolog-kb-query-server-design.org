* Design status
Approved by the project owner on 2026-09-18 for the bounded =prolog-star-kb= implementation slice.

* Canonical data boundary
Canonical StarIntel JSON is the durable source of truth. Prolog is a deterministic symbolic projection used for reasoning, graph traversal, explanation, and AI tool execution.

The active StarIntel core release is =0.9.1= while the immutable base schema remains =0.9.0=. A projection therefore records at least:

- release version;
- base schema version;
- profile and profile version;
- schema revision;
- expansion-registry content hash.

A Prolog projection must be disposable and rebuildable from canonical JSON. It must never become a second independently editable database.

* Goals
- Deterministically project canonical StarIntel JSON/NDJSON into Prolog.
- Preserve every JSON object, array, member, index, scalar value, scalar type, and path.
- Add semantic indexes for high-value StarIntel concepts without making those indexes lossy.
- Preserve source, evidence, provenance, temporal, reference, and relation semantics.
- Give actors and AI agents bounded semantic tools instead of arbitrary remote Prolog evaluation.
- Route reasoning by declared semantic capability instead of hard-coding one universal logic engine.
- Keep generated/derived conclusions separate from canonical source facts.
- Make projections replayable and attributable to the exact schema/profile contract.

* Non-goals for this implementation slice
- Bulk population of real-world facts.
- A universal ontology covering every StarIntel domain.
- Making Prolog the durable database.
- Trusting model-generated hypotheses as canonical facts.
- Selecting one logic engine as a universal winner.
- Exposing unrestricted shell, filesystem, dynamic-loading, or arbitrary Prolog goals to remote AI callers.

* Projection model
The lossless layer uses JSON Pointer paths.

#+begin_src prolog
star_json_object(DocumentId, Path).
star_json_array(DocumentId, Path, Length).
star_json_member(DocumentId, ParentPath, Key, ChildPath).
star_json_index(DocumentId, ParentPath, Index, ChildPath).
star_json_value(DocumentId, Path, Type, Value).
#+end_src

This layer is schema-additive by construction: a new JSON field remains queryable even before a specialized semantic predicate is added.

The semantic layer derives indexes such as:

#+begin_src prolog
star_doc(DocumentId, DType, Dataset, SchemaVersion, Version, ContentHash).
star_profile(DocumentId, Profile, ProfileVersion, SchemaRevision, ReleaseVersion).
star_ref(DocumentId, JsonPath, TargetId).
star_time(DocumentId, Key, Value, JsonPath).
star_source(DocumentId, SourceId, Kind, Locator, Credibility, Reliability, Hash).
star_evidence(DocumentId, EvidenceId, SourceId, Role, Claim, Confidence, Status).
star_provenance(DocumentId, Collector, Actor, Tool, Model, RunId, Method, ImportedFrom, Transform).
star_relation(RelationId, Subject, Predicate, Object, Directed, Negated, Confidence, Start, End).
#+end_src

Semantic indexes may be regenerated at any time from the lossless/canonical source.

* Determinism and identity
Documents are emitted in stable =_id= order. Object keys are emitted in lexical order; array order is preserved. Projection content hashes use canonical JSON serialization.

Projection metadata identifies the exact StarIntel contract used. Repeated projection of the same canonical input and manifest must produce byte-identical facts.

* Relation model
The relation projector supports the base v0.9 relation contract and additive v0.9.1 fields.

It recognizes canonical =subject/predicate/object= and compatibility =source/target= endpoints. It also emits:

- directed/undirected state;
- negation;
- confidence/weight;
- temporal interval;
- inverse predicate;
- scalar relation qualifiers.

Nested or future relation structures remain available through the lossless JSON-Pointer layer even when no semantic shortcut exists yet.

* Provenance and trust
Externally sourced or generated claims belong in canonical StarIntel JSON with source/evidence/provenance records.

AI/RLM output is candidate knowledge. It can propose new StarIntel documents, claims, relations, or evidence, but must pass the normal normalize -> validate -> provenance -> review/promotion boundary before appearing in a future canonical projection.

Derived Prolog conclusions are never silently asserted back into canonical JSON.

* AI reasoning tools
The initial AI surface is named and bounded:

1. =kb_document= — document/profile identity.
2. =kb_neighbors= — direct relation/reference neighborhood.
3. =kb_path= — bounded graph path.
4. =kb_explain= — relation + source + evidence + provenance + qualifiers.
5. =kb_timeline= — temporal observations.
6. =kb_contradictions= — explicit relation/evidence conflicts.
7. =kb_compare= — shared relation/reference features.
8. =kb_sources= — sources and provenance.
9. =kb_why_not= — distinguish supported, explicitly negated, and missing direct claims.
10. =kb_values= — query arbitrary scalar JSON-Pointer prefixes, including additive fields with no specialized semantic index.
11. =kb_referrers= — reverse lookup of documents/paths that reference an entity.
12. =kb_packet= — bounded RLM context packet containing identity, neighborhood, timeline, related source/provenance evidence, and contradictions.
13. =kb_route_reasoning= — return a semantic reasoning capability.

The tool compiler rejects unknown tool arguments and enforces bounded path depth. It does not accept raw caller-supplied Prolog goals.

* Reasoning capability routing
Following the approved ADARD logic-engine research, callers request semantics rather than engines.

Initial capability names include:

- =deterministic_rule_evaluation=
- =deterministic_explanation=
- =recursive_tabled_query=
- =answer_set_or_tabled_explanation=
- =probabilistic_query=
- =recursive_probabilistic_query=
- =bulk_datalog_closure=

Runtime policy may map those capabilities to SWI-Prolog, N-Prolog, XSB/PITA, ProbLog/cplint, s(CASP), Soufflé, or later engines after benchmark/selection policy.

* Actor, MCP, A2A, and StarLang boundary
=prolog-star-kb= owns projection semantics and safe reasoning predicates.

Actor, MCP, A2A, and StarLang adapters should generate or wrap the same AI tool catalog rather than reimplement ontology semantics. The same named tool should mean the same thing over actor, MCP, A2A, local Lisp, and StarLang surfaces.

Skynet/RLM is a consumer and orchestrator of these tools. It may recursively branch investigations and choose capability routes, but remains downstream of canonical JSON/provenance rules.

* Safety and bounded execution
- Only exported semantic predicates are AI-callable.
- Query depth and result count are bounded by caller/runtime policy.
- Write/ingest paths remain separate from read/reason paths.
- No shell, arbitrary directive, filesystem mutation, or unrestricted dynamic loading is part of the AI contract.
- Unknown arguments fail closed.
- Generated Prolog is cache/index state and must not contain secrets absent from canonical input.

* Verification requirements
- Same canonical input produces the same projection.
- Active release/base-schema/profile/revision identity is recorded.
- Unknown/additive JSON fields survive through JSON-Pointer facts.
- Relation/source/evidence/provenance shortcuts are emitted.
- AI tool schemas are machine-readable.
- Tool-goal compilation rejects undeclared arguments.
- Recursive graph depth is bounded.
- Python tests pass.
- Prolog modules load and smoke-test when SWI-Prolog is available.
- Repository RAGE/docs checks remain green.

* Deferred enrichment
After this slice is verified, the next design can add:

- first-class MCP server generation;
- Agent2Agent cards/tasks;
- StarLang =kb= and =reason= hammers;
- RLM evidence packets and recursive hypothesis/falsifier graphs;
- probabilistic adapters;
- tabled/path explanation with edge-level proof artifacts;
- embedding/vector candidate retrieval feeding symbolic verification;
- incremental projection/update indexes;
- corpus sharding and distributed materialization.

* Alternatives rejected
** Prolog as a separately editable source database
Rejected because it creates competing truth and replay problems.

** Only semantic predicates
Rejected because additive/future JSON fields would disappear until hand-mapped.

** Only generic JSON path facts
Rejected because agents would repeatedly reconstruct obvious StarIntel semantics and waste tokens/runtime.

** Arbitrary Prolog tool
Rejected because it destroys the bounded capability/security contract.

** One universal logic engine
Rejected by the approved ADARD engine-selection direction; engine selection is capability-specific.
