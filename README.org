#+title: Star KB
#+description: Deterministic StarIntel JSON-to-Prolog knowledge projection and bounded reasoning tools.

* Star KB

Star KB is the shared symbolic reasoning layer for StarIntel.

*Canonical StarIntel JSON is authoritative.* Prolog is a deterministic, rebuildable projection used for logic, graph traversal, explanations, and AI/RLM tooling. This avoids maintaining two competing truth stores.

The active StarIntel core release is =0.9.1= over the immutable =0.9.0= base schema. Projection metadata records release, schema, profile, revision, and expansion identity.

* prolog-star-kb

Project JSON/NDJSON:

#+begin_src sh
tools/prolog-star-kb project corpus.ndjson -o kb/generated/corpus.pl
#+end_src

List AI tool schemas:

#+begin_src sh
tools/prolog-star-kb tools
#+end_src

Compile a bounded tool call:

#+begin_src sh
tools/prolog-star-kb goal kb_path \
  '{"source":"starintel:person:a","target":"starintel:org:b","max_depth":5}'
#+end_src

See =docs/prolog-star-kb.md= for the data and tool contracts.

* star-kb-actors

The actor learning CLI stages model/research output as untrusted candidate knowledge, records votes and query traces, emits bounded review context, and delegates final admission to SWI-Prolog.

#+begin_src sh
tools/star-kb-actors init
tools/star-kb-actors submit candidate.json --actor extractor-a --run-id run-1
tools/star-kb-actors vote starintel:relation:r1 --actor reviewer-a --stance approve --run-id run-2
tools/star-kb-actors context --candidate starintel:relation:r1
tools/star-kb-actors audit --run-id audit-1
tools/star-kb-actors verify starintel:relation:r1 --run-id verify-1
#+end_src

Large LLM-generated NDJSON datasets can be streamed with =submit-batch=. This stages candidates only; it does not promote them into canonical truth.

The canonical actor/message protocol is written in StarLang under =spec/=. Candidate, vote, and verification records pin the exact SHA-256 of the StarLang learning spec in addition to its ID/version. Downstream libraries consume StarLang compiler manifests rather than maintaining parallel schemas. Formal admission rules live in =kb/core/star_verify.pl=.

See =docs/star-kb-learning-loop.md=.

* Architecture

#+begin_src text
canonical StarIntel JSON
          |
          v
  prolog-star-kb projector
          |
      +---+--------------------+
      |                        |
lossless JSON-Pointer facts    semantic indexes
      |                        |
      +-----------+------------+
                  |
          bounded Prolog API
                  |
       AI / RLM / actors / MCP / A2A / StarLang
#+end_src

Every JSON field remains queryable through path facts. Higher-value indexes add references, relations, time, evidence, sources, and provenance without throwing away unknown/additive fields.

AI callers receive named bounded tools rather than arbitrary remote Prolog execution.

* RAGE loop

1. Analyze observed state.
2. Gate execution explicitly.
3. Execute only the approved slice.
4. Verify with real evidence.
5. Recurse from observed results.

The approved slices are the JSON projection/reasoning foundation and the actor learning/admission loop. Bulk generated candidate staging is allowed; bulk canonical promotion remains a separate gate.
