* Star KB

Star KB is the shared symbolic knowledge repository for StarIntel. It is built around modular Prolog facts and rules, explicit provenance, stable predicate contracts, and a query-server boundary that lets actors consume shared knowledge without coupling themselves to repository paths or inventing incompatible local schemas.

The repository uses the RAGE research/design/implementation workflow. Research creates evidence. Design turns approved research into a bounded implementation proposal. Implementation only begins after explicit design approval.

* Repository shape

The Org tree under =roam/= is the project control plane and source of truth for research/design state.

* RAGE loop

1. *Analyze*: inspect current state, sources, constraints, contradictions, and unknowns.
2. *Gate*: record what evidence or approval is required before execution.
3. *Execute*: perform only the bounded action admitted by the gate.
4. *Evaluate*: record observed output, tests, failures, and new evidence.
5. *Recurse*: update state and begin the next loop from what actually happened.

A green build is evidence. It is not approval by itself.

* Workflow commands

Create a research note:

#+begin_src sh
python3 scripts/save-research.py \
  --project star-kb \
  --title "Investigation title" \
  --description "What needs to be established" \
  --draft
#+end_src

After a design is explicitly approved, promote it into the implementation slot:

#+begin_src sh
python3 scripts/implement.py roam/design/star-kb/<approved-design>.org
#+end_src

Record a terminal implementation result:

#+begin_src sh
python3 scripts/mark-design.py implemented \
  --project star-kb \
  --summary "Implemented the bounded slice" \
  --file <path> \
  --test "<verification command>"
#+end_src

Validate the repository:

#+begin_src sh
python3 scripts/sync.py
python3 scripts/sync.py --check
python3 scripts/validate-docs.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
#+end_src

* Document contract

Substantive Org documents carry a stable ID, title, description, status, file tags, an approval table, and a changelog. Research notes distinguish observed facts, inference, contradictions, and unresolved questions.

Do not load the entire corpus into an agent context for ordinary focused work. Load the active note, direct links, relevant index, source, and tests. Repository-wide audits are the exception.
